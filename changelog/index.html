    Changelog¶

    All notable changes to FlapSim are recorded here. The format follows Keep a Changelog and the project uses Semantic Versioning.

    [0.2.0] - 2026-10-28¶

    First release of FlapSim as an open platform. Everything below was built on the open-platform branch on top of the 0.1.0 single-robot simulator.

    Added¶

    • English translations of the quasi-steady derivation, the hover simplification and the two engineering notes (docs/derivations, docs/notes); the Chinese originals stay under docs/zh/.
    • Learning: flapsim.envs.SimulationEnv Gymnasium wrapper (observations from signals, actions to commands with smoothing), hover_reward, hover_terminated; flapsim.study.parameter_study (parallel grids); examples/rl/ IMU + TOF hover task with PPO training/evaluation scripts; examples/wing_length_study.py; extras rl, video, hdf5; RL CI job.
    • Components: sensors sensor/imu, sensor/rangefinder (plane or ray), sensor/encoder, sensor/wrench (load cell) with a shared conditioner (sample rate, low-pass, delay, noise, per-episode bias, quantisation); actuators actuator/dc_motor_crank (voltage-driven motor, gearbox and crank loaded by the aero torques) and actuator/servo (rate-limited, lagged PD); controllers controller/schedule and controller/callback; ForceArrows viewer overlay, record_video (GIF, PNG frames, MP4), recorder HDF5 export; flapsim record and flapsim run --overlay; examples hover_pid.py, sensors.py, lift_sweep.py, custom_aero_model.py, render_video.py.
    • Aerodynamics library: AeroEngine evaluating additive per-wing models with shared kinematics; models quasi_steady, rotational_lift, added_mass, wake_capture; modifier ground_effect; aero/stack plugin; atmosphere/standard (ISA density, wind, gusts, turbulence); force/body_drag; aero/cycle_averaged generalized to identified thrust-tilt and moment matrices with parameter files; flapsim sweep identification (frequency, gimbal and damping sweeps). docs/aero_models.md.
    • Plugin system: flapsim.core.Simulation with the phases pre_control, control, actuate, forces, mj_step, post_step, record; a signal bus (wings/left/alpha, cmd/stroke/frequency_hz, ...); plugin base classes; a registry addressed by kind/name with entry-point discovery (flapsim.plugins group); flapsim.sim/1 YAML/JSON simulation configs with per-plugin overrides.
    • Built-in plugins: actuator/sinusoidal_stroke, actuator/pd_position (with joint roles), aero/quasi_steady, aero/cycle_averaged, controller/hover_pid, recorder/memory (npz/csv export).
    • flapsim.testing.check_plugin conformance check for third-party plugins; flapsim plugins and flapsim run <config.yaml> --describe commands; flat_plate_simulation() helper.
    • Example robot ships sim.yaml (fixed base) and hover.yaml (floating base) next to its manifest.
    • Robot manifests (robot.yaml): wings with aero frames, stroke and feathering joints, planforms, mirror relations; model patches for joint dynamics, equalities, mass overrides and collision exclusion; when: free / when: fixed conditional patches.
    • flapsim.robot.load() accepting built-in names, manifests, bare URDF/MJCF files and MjSpec objects; builtin_robots(); RobotModel with Wing objects.
    • flapsim.wings: planform integrals from analytic profiles, chord polylines, planform polygons and STL mesh outlines; runtime Wing state.
    • flapsim.robot.flat_plate_flapper() parametric two-wing robot built in Python (no CAD needed).
    • flapsim inspect and flapsim run command line (python -m flapsim.cli).
    • The quasi-steady adapter now handles any number of wings from the manifest.
    • Per-wing mass_model (spar_plate, thin_plate, explicit) declared in wing coordinates and converted to each body frame, so mirrored wings share one description; hinge geometry (pitch_axis_fraction, leading_edge_offset) in the planform and the aerodynamic moment.
    • Geometry self-checks at load time: warnings when a wing's chord direction or a joint sign looks reversed.
    • docs/derivations/quasi_steady_model.md: frame conventions, equations, hinge geometry, the passive-feathering regime and the model correction.
    • Apache-2.0 license, NOTICE, contributing guide, code of conduct, citation file.
    • Test suite: aerodynamic unit tests, left/right symmetry test, fixed-base lift-sweep regression test, headless smoke tests.
    • GitHub Actions CI (ruff + pytest on Linux, macOS, Windows; Python 3.10-3.13).
    • ROADMAP.md describing the open-platform architecture and phases.

    Fixed¶

    • added_mass: the feathering part of the added mass was an explicit force built from a one-step finite-difference feathering acceleration, which diverged on the 0.06 g wings (force pinned at the 5 N limit). The added rotational inertia is now added to the feathering joint's armature (implicit); only the prescribed stroke and body accelerations stay explicit. New AeroModel.bind(robot) hook.
    • rotational_lift: used the signed flow speed, so the force did not flip between upstroke and downstroke and the passive feathering became asymmetric; it now uses the flow-speed magnitude, evaluated at the c²-weighted span centroid (exact while the flow keeps its sign, continuous through reversal).
    • ForceArrows cleared the scene when used with the offscreen renderer, so rendered videos showed only the arrows; it now appends to renderer scenes and clears only a viewer's private overlay scene.
    • Manifest equality constraints size their data from mujoco.mjNEQDATA, so the example robot loads with MuJoCo releases where that constant is 12 (reported against mujoco 3.17).
    • flat_plate_flapper: a fresh MjSpec interprets angles in degrees, so the builder's joint ranges were 57 times too small; it now declares radians, uses stiff limit solver constants and a spar-plate wing mass model, and produces positive lift with correctly phased passive feathering.
    • Actuators restore their configured targets and commands on reset(), so episodes are deterministic for a given seed.
    • Quasi-steady pitching moment: the earlier implementation multiplied the moment by sign(alpha), which made it independent of the flow direction and moved the centre of pressure to the opposite side of the hinge at each stroke reversal; the MuJoCo adapter compensated with a translational force flip. The moment is now -(x_le + (d_cp - x0) c) F_N with the centre of pressure fixed on the plate, the flip is gone, and the wing frame is defined by span and chord so the plate side is explicit. See docs/derivations/quasi_steady_model.md. Regression values were re-measured.

    Changed¶

    • SimCore is a thin wrapper that loads the robot's shipped setup through Simulation.from_config; its method names are unchanged.
    • Example robot moved to flapsim/assets/robots/single_thrust_flapper/ with its manifest and joint configuration; no robot names remain in package code.
    • SimCore loads any robot that provides extras.joints; PlateController, HoveringController and AveragedHoverAero take joint and body names from configuration instead of hard-coding them.
    • Documentation moved to docs/ (Chinese originals under docs/zh/), notebooks and scripts to examples/.
    • pyproject.toml: MuJoCo pinned to >=3.3,<4, project metadata, ruff config.

    Removed¶

    • flapsim.environment, flapsim.actuator, flapsim.controller and the example's joints.json, replaced by flapsim.core, flapsim.actuators, flapsim.controllers and the sim.yaml / hover.yaml setups.
    • Unused configuration bundle loader and JSON files superseded by the manifest.
    • Reinforcement-learning training code and trained policies (flapsim/rl). They return as examples built on the plugin API in a later phase.
    • Committed bytecode and MuJoCo log file.

    [0.1.0] - 2026-10-19¶

    Initial single-robot simulator: URDF import through MjSpec, quasi-steady blade-element aerodynamics, cycle-averaged hover model, PID hover controller.
