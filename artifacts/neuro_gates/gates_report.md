# 原环境内的 SNN/NEAT 方向：预备关口结果（2026-10-12）

**约束**：严格使用原 v3 环境接口。
- 传感：IMU，加上测距得到的高度。
- 执行：云台 α/β 在 ±0.3 rad 内；电机转速在 3115–3807 rad/s 内；每 2 ms 更新一次，经过 8.2 ms 的一阶平滑。

本次只改变 PID 的增益，或改变 PID 读到的姿态信号。用真值构造的"理想信号"只作为诊断上限，不是可部署的控制器。

**代码**：
- [gates.py](../../experiments/algorithms/neuro_gates/gates.py)：适应关口，以及理想姿态信号 `Oracle`；
- [diagnostics.py](../../experiments/algorithms/neuro_gates/diagnostics.py)：晃动测量、滞后扫描、云台脉冲。

**数据**：[adapt.json](adapt.json)。滞后扫描和推力单元扫描是用同一套代码（`gates.Oracle` 与 `gates.run`）的临时脚本跑的，结果直接摘录在下文；要复算，运行 `diagnostics.py lagscan`。

## 1. 机体随翅拍的晃动

条件：原 PID 悬停，常规案例，统计最后 2 s。翅拍频率 24.9 Hz。

| 信号 | 俯仰在 1×、2×、3× 翅拍频率处的幅值（°） |
|---|---|
| 下体（IMU 所在处）真实俯仰 | 4.41、0.01、0.17 |
| 真值经 30 ms 低通 | 0.92、0.00、0.01 |
| 真值按曲柄相位局部回归"去晃动"（derocked） | 0.00、0.00、0.00 |
| 环境给出的姿态（0.13 s 低通） | 0.22、0.00、0.00 |

## 2. PID 离不开 0.13 s 的慢姿态

条件：起飞的前 1.5 s 仍使用原传感器，之后改用理想信号；应力案例 3 个，每个 6 s。

| PID 读到的姿态 | 能飞满的增益组合（共 20 组） | 最好的倾角 RMS |
|---|---|---|
| 原传感器（kp×1、kd×1，即 v3 的 PID） | — | 10.0° |
| 去晃动真值，加 0.13 s 滞后 | 13 组至少飞满 2/3 | **8.45°**（kp×2、kd×1） |
| 去晃动真值，加 0.06 s 滞后 | 2 组飞满 1–2/3，0 组全部飞满 | 20–25° |
| 去晃动真值，加 0.03 s、0.01 s 滞后或无滞后 | **0 组** | — |
| 推力单元的姿态（去晃动或不去，任意滞后） | **0 组** | — |

增益范围：kp 为 0.25–2 倍，kd 为 0.5–8 倍。

## 3. 原因：两体结构的反向响应

在 t=3 s 加一个 50 ms 的俯仰云台残差（+0.035 rad），与同一案例不加脉冲的结果配对相减：
- 云台关节转动 +3.7°；
- 但下体（IMU 所在处）先**反向转 −2.3°**，推力单元只转 +1.5°；
- 随后两体以约 4–5 Hz 来回摆动，幅值约 ±2°，阻尼很小。

所以 IMU 看到的主要是云台推动时两体之间的反作用摆动，而不是推力方向。单变量 PID 只能靠 0.13 s 的慢传感器把闭环频带压到这个模态以下，才能保持稳定。

## 4. 适应关口：飞行中途变化是否需要在线适应

条件：t=4 s 时发生变化，每个案例 10 s；调参用 8 个应力案例，评估用 16 个新的应力案例。

| 变化 | 该条件下最优的增益 | 变化后倾角 RMS（评估集）：原 PID → 该条件最优 |
|---|---|---|
| 无变化 | kp×1.5、kd×1 | 9.94° → 8.67° |
| 推力损失（转速增益 ×0.9） | **相同** | 9.28° → 8.21° |
| 舵机刚度与阻尼 ×0.4 | **相同** | 9.99° → 8.70° |
| 下体质量 ×1.25（+2 g） | **相同** | 7.62° → 6.42° |
| 读数延迟升到 10 ms | kp×1、kd×0.85 | 11.72° → 10.01°（2/16 摔机） |

- 5 种情况里有 4 种，最优增益完全相同，所以几乎没有"在线适应"的空间。
- 以"所有条件下摔机最少、平均倾角最低"为准则选出的鲁棒增益（kp×1、kd×0.85）贴近稳定区的边缘（kd×0.7 必摔），在评估集上每种条件都摔了 2/16。
- **把 v3 的 PID 简单重调（kp×1.5），在所有条件下都比原 PID 低 1.1–1.7°**（16/16 配对都更低）。这个幅度大于 v3 学习型残差的约 1°（v4 证据，是选模验证集上的数字）。

## 4b. 原接口内的翅拍定时驱动（[timing.py](../../experiments/algorithms/neuro_gates/timing.py)）

**做法**：
- 每 2 ms 往 PID 的指令上加一个按翅拍相位锁定的量，之后照原样经过 LOW/HIGH 截断、8.2 ms 平滑和电机速度环。
- 时刻用真实曲柄角，因此结果是上限。
- 加 0.1 s 脉冲串，与同一案例不加的结果配对比较。
- "定时效应"取相反相位之差的一半，以抵消单边脉冲带来的平均升力变化。

**权限**（4 个常规案例；[timing_authority.json](timing_authority.json)）：

| 指令模式 | 俯仰角速度效应 | 前向速度效应 |
|---|---|---|
| 云台残差 +0.035 rad（参照） | 1.0× | 1.0× |
| **单边电机脉冲**（180° 相位窗内指令到上限，最佳相位 135°） | **4.1×** | **3.2×** |
| 单边电机脉冲，90° 窗 | 3.3–3.4× | 1.8–2.5× |
| 对称正弦调制（A=300，下半部被截断） | 2.7× | 2.1× |
| 向下脉冲（下限只余约 63 rad/s） | ≤0.7× | ≤0.5× |
| 云台随翅拍振荡 | ≤0.2× | ≤1.7× |

在不对称的上下限下，最有效的驱动是**单边、相位特定的脉冲**，而不是正弦。

**闭环**（8 个应力案例，在重调 PID 上叠加事件触发的脉冲律，俯仰误差大时才发；[timing_law_grid.json](timing_law_grid.json)、[timing_imu_law.json](timing_imu_law.json)）：

| 控制器 | 飞满 | 俯仰 RMS | 俯仰峰值 | 倾角 RMS | 高度误差 | 脉冲占空比 |
|---|---|---|---|---|---|---|
| 重调 PID | 8/8 | 7.1° | 16.8° | 8.8° | 7.5 cm | 0 |
| 脉冲律，理想状态与理想相位（阈值 0.5，60° 窗） | 8/8 | 2.4° | 7.0° | 5.6° | 13.2 cm | 1.9% |
| 脉冲律，理想值（阈值 0.8，90° 窗） | 8/8 | 3.3° | 8.6° | 6.1° | 10.1 cm | 1.2% |
| **脉冲律，只用 IMU**（锁相环相位、陷波陀螺、滞后姿态；阈值 0.5，60° 窗） | 8/8 | **3.0°** | **8.4°** | **5.9°** | **9.4 cm** | 0.9% |
| 脉冲律，只用 IMU（阈值 1.2） | 8/8 | 6.0° | 14.0° | 7.9° | 7.6 cm | 0.2% |

- 俯仰抑制和高度代价之间存在明确的取舍：每次脉冲都会增加升力，而下限只剩 63 rad/s，向下"抵消"几乎不起作用。
- 只用 IMU 的经典实现保留了大部分收益，是后续必须超越的基线。
- 横滚不受电机脉冲影响，所以总倾角的改善小于俯仰。

## 5. 结论

1. **"更好的本体感知帮助 PID"不成立**：PID 用不了更快的姿态信号。
2. **"进化可塑性做在线适应"在这些扰动下没有空间**：最优增益几乎不随条件变化。
3. **原环境的性能瓶颈**是"两体反向响应、翅拍晃动、慢姿态传感器"共同限制了单变量 PID 的频带。能否突破，取决于多变量的动态控制，也就是同时利用陀螺、加速度计和指令历史。
4. **v3 的 PID 没有针对应力场景调参**。今后任何学习方法，都必须和"同预算重调的 PID"比较。
5. **原接口内存在一个"按相位发脉冲"的通道**（第 4b 节）。最优形式是事件触发、相位锁定的单边脉冲，性质上就是脉冲序列，因此 SNN 与 NEAT 在结构上契合。另外，抑制俯仰与升力预算之间的取舍，正是学习型控制器可能改进的地方。
6. **仍未回答：多变量动态控制还有多少性能空间？** 可以用"理想全状态线性反馈"做上限：反馈去晃动的下体角度与角速度，以及云台角度与角速度，用 CEM 调参。若空间大，"进化脉冲网络学到 PID 无法表示的动态补偿"才值得做；若空间小，原环境里任何控制器都难有明显的性能提升。
